# Minimum Spanning Tree の実装解説

[使用法に戻る](../minimum_spanning_tree.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/minimum_spanning_tree.hpp)

## 目的と基本原理

全頂点を連結する閉路のない辺集合のうち、重みの合計が最小のものを求めます。
Kruskal法では辺を軽い順に見て、現在異なる連結成分を結ぶ辺だけを採用します。
例えば三角形の辺重みが1、2、4なら、1と2の辺を選び、閉路を作る4の辺を捨てます。
もともと非連結なら、各成分で同じ処理を行った最小全域森になります。

## 内部データ

`n_` は頂点数、`edges_` は追加順の辺リストです。
`add_edge` は末尾に追加し、その添字を辺IDとして返します。
`build` 内の `order` は辺IDを重み順に並べた配列です。
保存した辺自体をソートしないので、結果の `edge_ids` から `get_edge` で元の端点・重みを参照できます。
同じ重みの辺は辺IDで順序を決めるため、結果が再現可能になります。
`uf` は同梱ACLのDSUで、採用辺だけによる連結成分を管理します。
`result.cost` は採用辺の重みの合計、`component_count` は現在の成分数です。

## 処理の流れと不変条件

初期状態では辺がなく、n個の孤立点があります。
これは各 `build` が作る新しいDSUの状態です。登録辺と以前の結果には変更を加えません。
辺の両端が既に同じ成分なら、採用すると閉路になるためスキップします。
異なる成分なら採用して併合し、成分数を1減らします。
したがって採用辺は常に森であり、採用辺数は常に `n - component_count` です。
自己ループは必ず同一成分判定で除外されます。多重辺も特別扱いは不要です。

採用する辺は、その時点の成分を外部へ結ぶ最小重みの辺です。
既に選んだ辺を含む最小全域森があると考え、今回の辺がそこになければ追加します。
同じ入力成分内の木にできた閉路には、その成分境界をまたぐ別の辺があります。
その辺を今回の辺と交換してもコストは増えません。
よって採用を繰り返しても最適解へ拡張できるという不変条件が保たれます。
この議論は負の重みでも成立します。

成分数が1になったら全頂点がつながり、それ以上採用できる辺はないので終了します。
非連結の場合は全辺を調べます。入力辺が結ぶ頂点は最終的に同じ成分になるため、
最後の成分数は入力グラフの成分数と一致します。
空グラフでは併合せず成分数0を返します。

## 計算量の根拠

添字配列のソートに $O(m\log(m+1))$、
DSUの初期化に $O(n)$、辺ごとの連結判定・併合に合計 $O(m\alpha(n))$ かかります。
添字配列は $O(m)$、DSUと採用辺配列は $O(n)$ なので、追加空間は $O(n+m)$ です。
辺数カウントなどの追加管理は不要なため、軽量なACLのDSUを使用します。

## 改造時の注意点

有向辺の向きは扱いません。有向の最小全域木には別のアルゴリズムが必要です。
負の自己ループであっても、全域木に閉路は含めないため採用してはいけません。
同様に負の辺でも閉路を作るなら除外します。
最大全域木へ変更する場合は比較を降順にし、重みの符号反転による整数最小値のオーバーフローを避けます。
合計は重みと同じ型で計算するため、中間和も含めて収まる型を使います。
辺を追加しても以前の結果は自動更新されません。必要なら `build` を再実行します。
差分更新ではなく全辺のソートと新しいDSUによる再計算です。
既存辺の削除・重み変更のAPIはなく、それらが必要な場合は新しいオブジェクトを作ります。

## 改造後の確認

空グラフ、1頂点、孤立点、連結・非連結、負の重み、自己ループ、多重辺、
同重みの選択順、32ビットを超える合計を確認します。
小さいランダムグラフでは全辺部分集合を列挙し、入力と同じ成分数かつ辺数がn-cのものから
最小コストを選ぶ愚直解と比較します。採用辺の重複がなく入力が不変なことも確認します。
これらと20万頂点の道のケースを `test/minimum_spanning_tree_test.cpp` に用意しています。
`add_edge` のID、`get_edge` の内容、`build` の繰り返し、計算後の辺追加で最適解が変わるケース、
以前の結果が保存されることも確認します。
