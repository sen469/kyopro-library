# Dynamic Union Find の実装解説

[使用法に戻る](../dynamic_union_find.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/dynamic_union_find.hpp)

## 目的と基本原理

文字列や大きな整数をそのまま頂点名にできる Union Find です。`"Tokyo"` と `"Osaka"` を登録すると内部では0、1の連番に変換し、配列上の通常の Union Find に処理を移します。全キーを先に座標圧縮できない場合に使えます。

## 内部データ

`id_` はキーから番号へのハッシュ表、`keys_` は逆変換表です。`parent_or_size_` は負のサイズまたは親番号を持ち、`group_count_` は登録済み要素の成分数を保持します。

## 処理の流れと不変条件

`add` は未登録キーだけを単独成分として追加します。`leader_index` は経路圧縮を行い、`merge` はサイズ併合します。`leader_id(a)` は `leader_index(add(a))` なので、キーの登録番号ではなく現在の根番号を返します。`same` や `size(a)` も未登録キーを自動登録するため、読み取りに見える操作で要素数が変わります。

## 計算量の根拠

キーのハッシュ・比較が定数時間なら、連結操作は期待ならし $O(\alpha(N))$、空間は $O(N)$ です。文字列キーでは文字数に依存するハッシュ費用も必要です。`reserve` は再確保を減らすだけで要素を登録しません。

## 改造時の注意点

自動登録を禁止するなら `add` を呼ぶ全公開操作を見直します。`index` は未登録を許しません。`key(i)` が返す参照は `keys_` の再確保で無効になるので、登録中に保持するならコピーします。根番号は併合で変わるため永続 ID として使えません。

## 改造後の確認

同じキーの再登録、未登録キー同士の `same`、自己併合、カスタム Hash/Pred の一致、登録後の `leader_id` と `leader` の対応を確認します。
