# Directed MST の実装解説

[使用法に戻る](../directed_mst.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/directed_mst.hpp)

## 目的と基本原理

指定した根から全頂点へ届く、重みの合計が最小の有向木を求めます。
根以外には入辺がちょうど1本必要です。各頂点で最小の入辺を選び、
閉路ができたらそれを縮約して、外から入る辺を選び直すChu–Liu/Edmonds法です。

例えば `0->1:5, 0->2:6, 1->2:1, 2->1:1` では、
最小の入辺だけを選ぶと1と2の間に閉路ができます。
その閉路を縮約し、外から入る辺で1本を置き換えると、合計6の木になります。

## 内部データ

`edges_` は変更しない元の辺リストです。
`heaps[v]` は成分vに入る辺を管理するleftist heapの根、
`chosen[v]` はその成分で選んだ入辺の元のIDです。
`uf` は現在の成分を求める経路圧縮付きUnion-Findです。
`visited` に探索開始頂点を記録し、同じ探索中の成分へ戻ったことを検出します。
根は初めから処理済み扱いにして、入辺を選びません。

閉路を縮約すると新しい成分IDを作ります。
`children`・`tree_parent` はこの縮約の親子関係、
`leaf_count` は成分に含まれる元の頂点数です。
元の頂点が葉、縮約成分が内部頂点となる森を形成します。
各縮約は2個以上の成分をまとめるため、成分IDは全体で2n未満です。

## 入辺の遅延減算とヒープ

辺ごとに1個だけヒープノードを作ります。
キーは補正後の重みで、同重みなら元の辺IDを比較します。
各ノードに左右の子・右側の高さに相当するrank・遅延減算値を持たせます。
左右の子を必要に応じて交換し、左のrankが右以上というleftist heapの条件を保ちます。
右側の経路が対数長になるので、併合と最小辺の削除は対数時間です。

併合は右の経路を配列 `path` に保存し、逆順に戻して組み直します。
再帰による呼び出しスタックは使いません。
成分で重みcの入辺を選んだら、残りのヒープ全体からcを減算します。
これは「既に選んだ入辺を別の辺へ置き換える追加費用」をキーにする操作です。
部分木全体の減算をlazyとして根に保持し、子を操作するときに伝播します。

## 探索と閉路の縮約

未処理の成分で最小入辺を選び、その始点側の成分へ進みます。
ヒープに残った辺の始点が同じ成分に属していれば、それは縮約によって内部辺になったものなので捨てます。
外から入る辺がなくなった場合、その成分は根から到達できず、全体の構築は失敗です。
自己ループと元の根への入辺は最初からヒープに登録しません。

同じ探索で訪問した成分へ戻ると閉路です。
選んだ入辺をたどって全メンバを列挙し、そのヒープを併合します。
列挙が終わってからUnion-Findの親を新しい成分IDへ変更します。
途中で変更すると、閉路のメンバを最後までたどれなくなるためです。

閉路の各入辺は、それぞれの行き先で最小の辺です。
外から辺u->vを選ぶとき、閉路内で選ばれていたvの入辺を外せば閉路を切れます。
その差分費用がヒープの補正後の重みです。
この対応により縮約グラフの最適解を元のグラフの最適解へ展開できます。
既に選んだ入辺はヒープから除いておきますが、IDを `chosen` に保存して復元に使います。

## 採用辺と親の復元

縮約木の葉をDFS順に並べ、各成分に含まれる葉の連続区間を求めます。
区間の左端が `begin`、長さが `leaf_count` です。
DFSはスタックで行います。

縮約成分に採用された入辺の行き先をvとすると、
vを含む子成分の入辺だけをその辺で上書きします。
他の子には閉路を作った際の `chosen` をそのまま残します。
どの子がvを含むかは葉の区間に対する包含判定で分かります。
これを親から子へ行えば、入れ子の縮約も元の頂点まで展開できます。

元の頂点に届いた入辺u->vから `parents[v] = u` を設定します。
根の親は-1のままです。採用辺IDを昇順に並べ、元の重みを足して合計コストを返します。
`parent(v)` は保存した親配列を参照するだけなのでO(1)です。

## 計算量の根拠

各辺のヒープノードは1個で、取り出しも高々1回です。
ヒープの併合・取り出しはO(log(m+1))、遅延減算はO(1)です。
縮約成分と縮約木の辺はO(n)個で、縮約木の走査・復元はO(n)です。
復元時は各内部頂点の子を高々1回ずつ調べるため、深さに比例して祖先をたどる必要はありません。

Union-Findは縮約成分へ代表元を付け替えて経路圧縮を行います。
rankによる併合ではないため、ここではその操作もならしO(log(n+1))の上界で数えます。
最後の辺IDのソートも含め、時間は $O((n+m)\log(n+m+1))$、追加空間は $O(n+m)$ です。
演算・比較・コピーが定数時間の重み型を想定しています。

旧実装は縮約のたびに全辺リストを保存したため、深い縮約でO(nm)のメモリを使っていました。
現在はヒープを破壊的に併合し、縮約木だけを残すので、その問題を避けています。
ヒープは各build内で新しく作るため、登録辺や以前の結果は変更しません。

## 改造時の注意点

減算対象は元の重みではなく、現在のヒープの補正後の重みです。
lazyの伝播を行わずにヒープの子を組み替えると、別成分の辺へ誤った補正が適用されます。
縮約木の親と、経路圧縮されるUnion-Findの親は別に保持してください。
復元時には元の辺の行き先が属する子を置き換えます。辺の始点で判定してはいけません。

減算、lazyの累積、最終合計の中間オーバーフローに注意してください。
浮動小数点では補正による丸め誤差が生じます。
全辺を反転すれば根へ集まる木にも使えますが、元の辺の向きは呼び出し側で管理します。

## 改造後の確認

小さいグラフの全辺部分集合を列挙する愚直解と比較し、
採用辺の入次数・到達性・コストと、親配列の整合性を確認します。
単一・複数・入れ子の閉路、到達不能、負の重み、多重辺、同重み、根変更、辺追加後の再構築を含めます。
長い道に加え、100001頂点・199999辺で縮約が深く入れ子になる回帰テストを
`test/directed_mst_test.cpp` に用意しています。
