# Trie の実装解説

[使用法に戻る](../trie.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/trie.hpp)

## 目的と基本原理

文字列の共通接頭辞を1本の経路として共有します。`app` と `apple` は先頭3文字を共有し、`app` の終端と `apple` の終端だけが異なります。全候補を毎回比較せず、検索文字数に応じて下降できます。

## 内部データ

`nodes_` の各ノードは `next[CHAR_SIZE]`、`pass_count`、`end_count` を持ちます。`next` は文字 `c-BASE` に対応する子番号で、-1なら未生成です。通過数はその接頭辞を持つ文字列数、終端数は完全一致する文字列数です。根は空接頭辞です。

## 処理の流れと不変条件

`insert` は根と通過ノードの個数を増やし、終端で `end_count` を増やします。`erase` は完全一致が存在する場合だけ同じ経路の個数を減らします。文字列 `app` 自体がなくても `apple` があれば `prefix_count("app")` は正です。ノードは削除後も残ります。

## 計算量の根拠

文字数Lの検索・削除は $O(L)$、挿入は新規ノードの配列初期化を含め $O(L\cdot CHAR\_SIZE)$ の上界です。固定文字種なら $O(L)$。空間は過去に作ったノード数Vに対して $O(V\cdot CHAR\_SIZE)$ です。

## 改造時の注意点

`char_id` に範囲チェックはないため、文字種の変更は BASE と CHAR_SIZE を必ず合わせます。現在の `starts_with` は経路の存在だけを見るので、最後の該当文字列を削除した後でも true になり得ます。現在残っている文字列の存在を知りたいなら `prefix_count(prefix)>0` を使います。この挙動の変更は別途行う必要があります。

## 改造後の確認

空文字列、同じ文字列の複数登録、片方が他方の接頭辞、全削除後の検索を確認します。multiset 内で実際に前方一致する個数と `prefix_count` を比較します。
