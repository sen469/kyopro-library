# Cycle Detection の実装解説

[使用法に戻る](../cycle_detection.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/cycle_detection.hpp)

## 目的と基本原理

有向・無向グラフから閉路を1つ復元します。有向の道 `0→1→2` に `2→0` があると、探索途中の祖先へ戻れるため閉路です。単に訪問済みかだけでは、探索が終了した別枝へ向かう有向辺を誤判定します。

## 内部データ

`cycle_detection<Directed>` は辺をID付き隣接リストに保存します。有向・無向とも `color` は未訪問0・探索中1・終了2、`parent` はDFS木の親、`parent_edge` は親へ戻る辺のIDです。`build` のローカル配列なので毎回初期化されます。

## 処理の流れと不変条件

有向版は色1への辺を見つけると親をたどり、返す列の順序を反転します。無向版でも色1の祖先への辺で閉路を復元しますが、親へ戻る探索辺だけをIDで除外します。自己ループは1頂点の閉路です。返り値は始点を末尾に重複させず、最後から最初への辺で閉じます。

## 計算量の根拠

DFS と高々1回の経路復元なので時間・空間とも $O(N+M)$ の範囲です。明示的なスタックに頂点と次に調べる辺位置を保存するため、長い道でも再帰スタックは使いません。

## 改造時の注意点

無向版は親『辺ID』だけを飛ばすため、平行な別の辺による2辺閉路も検出します。隣接リストコンストラクタは小さい端点側から無向辺を登録し、IDを生成します。全隣接辺を調べ終えた時だけ色2に変える順序を保ってください。

## 改造後の確認

自己ループ、平行2辺、有向 DAG の合流、長い閉路、複数成分を確認します。返った頂点列の全辺と末尾から先頭の辺が実在するか検査します。
