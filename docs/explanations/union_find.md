# Union Find の実装解説

[使用法に戻る](../union_find.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/union_find.hpp)

## 目的と基本原理

辺を追加しながら連結性を調べます。毎回 DFS をすると辺の追加ごとにグラフ全体を探索するため、連結成分を根付き木で表します。`merge(0,1)`、`merge(1,2)` の後は3頂点の根が同じになり、根の一致だけで連結性を判定できます。

## 内部データ

`parent_or_size_` は根なら負の成分サイズ、根以外なら親番号です。`edge_count_` と `unique_edge_count_` は根でのみ有効です。`edges_` は端点を小さい順に並べて64ビットに詰めた辺の集合、`group_count_` は現在の成分数です。

## 処理の流れと不変条件

`leader_internal` は親を再帰的にたどり、通った頂点の親を根へ付け替えます。`merge` は小さい成分を大きい成分へ付け、根のサイズと辺数を合算します。同じ成分への辺追加でも辺数は増えますが、成分数は減りません。例えば3頂点の道に端点間の辺を追加すると、頂点数3・辺数3となって閉路ができます。

## 計算量の根拠

サイズ併合と経路圧縮により連結操作はならし $O(\alpha(N))$ です。辺の記録にはハッシュ表の期待ならし $O(1)$ が加わり、最悪定数時間ではありません。メモリは異なる辺数を $M$ として $O(N+M)$。`groups` は全頂点を巡回して列挙する処理です。

## 改造時の注意点

成分情報を追加する場合は、根が入れ替わった後に合算します。単なる集合の併合ではなく、`merge` 自体が辺の追加を意味する点を維持してください。多重辺を含む連結成分の木判定は `edge_count(v) == size(v)-1`。重複なし辺数だけで判定すると多重辺を見落とします。辺管理を外すなら対応する取得 API も見直します。

## 改造後の確認

孤立点、逆向きに同じ辺を追加、自己ループ、既に連結な2頂点、異なるサイズの成分併合を確認します。小さいグラフの BFS と成分・辺数を比較し、失敗する併合で成分数が減らないことも確認します。
