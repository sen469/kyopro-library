# Balanced Binary Search Tree の実装解説

[使用法に戻る](../balanced_binary_search_tree.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/balanced_binary_search_tree.hpp)

## 目的と基本原理

順序付き多重集合に順位取得を加えた Treap です。`[2,2,5]` はキー2のノードに個数2、キー5に個数1を持ち、0始まりの順位1は2、順位2は5です。平衡性は回転と乱数優先度で保ちます。

## 内部データ

`key` は値、`count` は同値要素の個数、`size` は重複込み部分木サイズです。`comp` が順序を定め、等値は双方向とも比較が偽で判定します。`priority` は親より子が小さくならないヒープ条件を持ちます。

## 処理の流れと不変条件

挿入は比較に従って下降し、優先度が逆転したら回転します。削除は `count` を減らすか、左右の木を `merge` してノードを取り除きます。`kth` は左サイズと `count` で順位を振り分け、`order_of_key` は右へ進むたび左部分木と現在ノードの個数を足します。回転前後で中順順序を保存し、下側から `update` します。

## 計算量の根拠

異なるキー数を $D$ とすると通常操作は期待 $O(\log(D+1))$、ノード空間 $O(D)$。イテレータはノードではなく順位 `index` を持ち、参照のたびに `at` を呼ぶため逆参照は期待対数時間です。`to_vector` は重複込み要素数に比例し、コピーはノード数に比例します。

## 改造時の注意点

比較は厳密弱順序にしてください。集約を追加するなら `update` と回転・挿入・削除の呼び出しを確認します。イテレータの順位は挿入削除で別要素を指し得ます。`random_access_iterator_tag` があっても逆参照は定数時間でなく、標準的なランダムアクセス反復子の計算量を仮定できません。

## 改造後の確認

重複の1個削除と全削除、逆順 Compare、全順位、上下界をソート済み vector と比較します。回転が多い昇順入力と、コピー・ムーブ後の操作も確認します。
