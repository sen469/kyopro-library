# ACL Min Cost Flow の実装解説

[使用法に戻る](../../atcoder/mincostflow.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/atcoder/mincostflow.hpp)

このリポジトリに同梱された実装を対象としています。

## 目的と基本原理

指定量まで流すときの費用を最小化します。1単位費用2の経路が容量1、費用5の経路が容量2なら、流量0/1/3で費用0/2/12になります。この折れ線の折点を返すのが `slope` です。

## 内部データ

`_edges` に元辺と流量を保存し、計算時に CSR の残余グラフを構築します。`dual_dist[v]` はポテンシャルと最短距離、`prev_e` は復元用逆辺番号。`que_min` は距離が増えない候補、`que` はその他のヒープです。

## 処理の流れと不変条件

逐次最短路法で、現在の最安な増加経路へボトルネック容量だけ流します。逆辺の負費用をそのまま Dijkstra に渡さず、費用を $c(u,v)+dual[u]-dual[v]$ に変換します。これは各s-t経路に同じ定数を加えるため経路の優劣を保ち、ポテンシャル更新で残余の有効辺を非負に保ちます。`dual_ref` 後の `-dual[s]` が追加1単位の費用です。同じ傾きの連続折点は削除します。

## 計算量の根拠

増加処理回数をAとすると、CSR 構築に $O(N+M)$、各回の探索に $O(N+M\log(M+1))$ の上界があります。整数容量ではAは流量以下ですが、容量まとめ流しにより小さくなることがあります。空間 $O(N+M)$ に折点列が加わります。

## 改造時の注意点

追加する辺の費用は非負です。assertを外すだけで負費用に対応できるわけではなく初期ポテンシャルの計算が必要です。この実装では呼出しごとにポテンシャルを初期化するため、`flow/slope` の複数回呼出しは使用法の制約通り避けます。距離・費用×流量のオーバーフローにも注意します。

## 改造後の確認

異なる単価の経路、同単価の折点統合、流せる量不足、容量0、逆辺で流し直す例を確認します。小さい容量で可能な辺流量を列挙し最小費用と比較します。
