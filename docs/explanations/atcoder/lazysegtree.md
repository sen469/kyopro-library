# ACL Lazy Segtree の実装解説

[使用法に戻る](../../atcoder/lazysegtree.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/atcoder/lazysegtree.hpp)

このリポジトリに同梱された実装を対象としています。

## 目的と基本原理

区間の各要素を更新する代わりに、部分木全体へ作用を予約します。長さ4の区間へ3を加えるなら、その区間和を12増やし、子への更新は必要になるまで保留できます。

## 内部データ

`d` は集約値、`lz` は内部ノードで子へまだ渡していない作用です。`S,op,e` が集約、`F,mapping,composition,id` が作用を表します。ノード自身の `d` には予約した作用が既に反映されています。

## 処理の流れと不変条件

`all_apply` は `d` を変更し、古い予約gへ新しいfを重ねて `composition(f,g)` を保存します。`push` は予約を両子へ渡して自分をidへ戻します。区間操作はまず境界経路の予約を押し下げ、完全に含まれるノードへ作用し、最後に境界の祖先を再計算します。全区間に予約が残るノードを子から不用意に再計算しないよう、境界判定をしています。

区間和へのアフィン変換 $x\mapsto ax+b$ ならSに和と長さを保存し、`mapping` は $(sum,len)\mapsto(a\,sum+b\,len,len)$。gの後にfなら合成係数は $(a_fa_g,a_fb_g+b_f)$ です。

## 計算量の根拠

木の高さだけ境界を処理するため、点/区間更新・取得・境界探索は $O(\log N)$、構築・空間 $O(N)$。これらは各コールバックと状態コピーが定数時間の場合です。

## 改造時の注意点

`mapping(f,op(x,y))=op(mapping(f,x),mapping(f,y))` が必要です。更新の合成順を逆にすると代入と加算などで結果が変わります。区間長はライブラリが mapping に渡さないため、必要ならSへ含めます。条件付き更新など単純な作用で表せない操作はこの枠組みの外です。

## 改造後の確認

全体更新後の1点取得、代入→加算と加算→代入、重なる区間、空区間、更新後の境界探索を配列と比較します。
