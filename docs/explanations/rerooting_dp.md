# Rerooting DP の実装解説

[使用法に戻る](../rerooting_dp.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/rerooting_dp.hpp)

## 目的と基本原理

すべての頂点を根にした木 DP を、根ごとの再計算なしで求めます。木の各辺を切った片側の答えを両方向に渡せれば、どの頂点でも全隣接方向からの情報を合成できます。距離最大値なら、各隣接方向の高さに辺長を足して最大を取ります。

## 内部データ

`graph_` は追加順を保つ隣接リストです。各辺の `id` はその頂点から隣接頂点へ向かう方向のID、`rev` は逆向きの辺の隣接リスト内の位置です。
`parent_` は最後の `build(root)` で決めた親、`order_` は親が子より前に現れる訪問順、`dp_` は子側のみの答えです。
`built_` は部分木DPの構築が完了したかを表します。頂点状態がR、隣接方向の集約がMで、`f_ve` が辺を付加する変換、`f_ev` が頂点での仕上げです。

## 処理の流れと不変条件

### build

指定された根から親と訪問順を求め、逆順の `order_` で下から `dp_` を計算します。
子 `to` の値を `f_ve(dp_[to], edge.id)` で変換し、追加順に集約して `f_ev` を適用します。
返り値は部分木DPのコピーです。根に対応する要素だけは木全体を含みます。
毎回、親・訪問順・DPを初期化するため、根や外部データを変えた再構築が可能です。

### reroot

正順の `order_` で親側の寄与 `parent_contrib` を伝播します。
各隣接方向の寄与を `values` に保存し、右からの累積 `suffix` と、走査しながら更新する左累積 `prefix` を使います。
子i以外の情報は `op(prefix, suffix[i+1])` です。逆演算が不要なので、最大値のように引き算できない演算も扱えます。
親側の寄与も元の隣接位置に置き、左右の順序を変えないため、非可換演算にも対応できます。

子に親側の値を渡すときは、`f_ev` で現在の頂点を付加した後、逆辺のIDで `f_ve` を呼びます。
例えば `add_edge(u,v,idx,xdi)` では、uがv側を取り込む際はidx、vがu側を取り込む際はxdiです。
`rev` で逆辺へ定数時間でアクセスできるので、隣接リストを検索する必要がありません。

親側の寄与は呼び出しごとのローカル配列であり、保存した `dp_` は書き換えません。
このため `reroot()` を繰り返しても寄与が二重加算されません。

## 計算量の根拠

`build` は各頂点・各辺を定数回処理します。`reroot` は各頂点で次数に比例する配列を構築し、次数の総和は2(N-1)です。
各コールバックと状態の構築・コピーが定数時間なら、それぞれ時間・追加空間 $O(N)$ です。
再実行も1回ごとに同じ計算量がかかります。訪問順を配列に保存するため、長い道でも再帰スタックは増えません。

## 改造時の注意点

連結な木が前提です。`op` は結合則と単位元を持つ必要があり、非可換演算なら辺の追加順が DP の意味に合うか確認します。
逆辺のIDを現在の辺のIDへ置き換えると、方向別に重みが異なる場合に誤答します。
重みや法などコールバックが参照する外部データの変更は自動検知できません。変更後は必ず `build` を呼び直します。
構造の動的な辺追加・削除を処理するライブラリではありません。木を変更する場合は新しいオブジェクトを作ります。
空グラフでは `build()` と `reroot()` は空配列を返し、非空の根へのアクセスは行いません。

## 改造後の確認

空グラフ、1頂点、道、星、辺の入力順を変えた場合を確認します。
小さい木で各頂点を根に通常の DP を実行して、`build` の部分木配列と `reroot` の全頂点の答えを比較します。
方向別ID、文字列結合など非可換な演算、RとMが異なる型、外部重み変更後の再構築、別の根での再構築、`reroot` の繰り返しを確認します。
これらと20万頂点の道のケースを `test/rerooting_dp_test.cpp` に用意しています。
