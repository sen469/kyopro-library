# Tree Centroid の実装解説

[使用法に戻る](../tree_centroid.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/tree_centroid.hpp)

## 目的と基本原理

頂点を1つ取り除いたときに、どの残存成分も大きくなりすぎない頂点を求めます。
頂点数を $n$ とすると、残る成分の最大サイズが $\lfloor n/2\rfloor$ 以下である頂点が重心です。
例えば道 `0-1-2-3` では、1を取り除くと成分サイズは1と2、2を取り除くと2と1なので、重心は1と2です。

## 内部データ

- `parent[v]`: 頂点0を根としたときの親。根自身の親は0とします。
- `order`: 親が子より前に現れる訪問順。末尾に子を追加し、先頭から走査します。
- `subtree_size[v]`: 自分自身を含む部分木の頂点数。
- `largest`: 頂点 `v` を除いたときの最大連結成分サイズ。

空グラフでは、根へアクセスする前に空配列を返します。

## 処理の流れと不変条件

まず根0から親と訪問順を求めます。木では親以外の隣接頂点は未訪問の子です。
`order` を逆順にすると子が親より先に処理されるため、各頂点の初期値を1として
`subtree_size[parent[v]] += subtree_size[v]` を行えば、すべての部分木サイズが確定します。
根は自分へ加算しません。

頂点 `v` を取り除いたときにできる成分は、子 `to` の部分木と、親側の部分に分かれます。
それぞれのサイズは `subtree_size[to]` と `n - subtree_size[v]` です。
根の親側サイズは0なので、根も同じ式で判定できます。
木には子の部分木同士をつなぐ別の辺がないため、この列挙で全成分を過不足なく扱えます。
最大値が `n / 2` 以下なら、定義どおりその頂点は重心です。

最後の判定を頂点番号の昇順で行うので、結果のソートは不要です。
辺リスト版は両方向の隣接リストを作り、同じ処理へ委譲します。

## 計算量の根拠

訪問順の作成と判定では、それぞれ各頂点・各辺を定数回だけ処理します。
部分木サイズの計算は各非根頂点を1回処理します。木の辺数は $n-1$ なので全体で $O(n)$ です。
3本の配列と辺リスト版の隣接リストに $O(n)$ の空間を使います。
再帰を使用しないため、長い道でも呼び出しスタックの深さは増えません。

## 改造時の注意点

現在のAPIは木であることを前提とし、一般グラフを完全に検証するものではありません。
森へ対応させる場合は成分ごとの走査と頂点数が必要です。
頂点重み付きに変える場合は非負重みの部分木和・全体和で判定し、加算時のオーバーフローも考慮します。
辺重みの付与だけでは、この頂点数に基づく重心は変わりません。

重心分解へ拡張するときは、削除済み頂点を除く現在の成分ごとに部分木サイズを求め直します。
元の木全体の `n` や `subtree_size` を再利用してはいけません。
単一重心を求めるだけなら結果の先頭を選べますが、空グラフを別扱いしてください。

## 改造後の確認

空グラフ、1頂点、2頂点、奇数長・偶数長の道、星、平衡木を確認します。
小さいランダム木では、各頂点を実際に除いて残る連結成分を列挙する愚直解と比較します。
頂点番号の置換・辺の順序や向きの変更でも結果が正しいこと、長い道でも処理できることを確認します。
これらのケースは `test/tree_centroid_test.cpp` に用意しています。
