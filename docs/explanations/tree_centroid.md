# Tree Centroid の実装解説

[使用法に戻る](../tree_centroid.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/tree_centroid.hpp)

## 目的と基本原理

頂点を1つ取り除いたときに、どの残存成分も大きくなりすぎない頂点を求めます。
頂点数を $n$ とすると、残る成分の最大サイズが $\lfloor n/2\rfloor$ 以下である頂点が重心です。
例えば道 `0-1-2-3` では、1を取り除くと成分サイズは1と2、2を取り除くと2と1なので、重心は1と2です。

頂点重み付き版では、サイズを非負の頂点重みの合計に置き換えます。
全体の重みを $W$ とすると、残る各成分の重みが $W/2$ 以下なら重心です。
道 `0-1-2` に重み `{10,1,1}` を与えると、頂点0を除いた残りの重みは2なので重心は0です。

## 内部データ

- `parent[v]`: 頂点0を根としたときの親。根自身の親は0とします。
- `order`: 親が子より前に現れる訪問順。末尾に子を追加し、先頭から走査します。
- `subtree_weight[v]`: 自分自身を含む部分木の重みの合計。型は入力と同じ `T`。
- `total`: 全頂点の重みの合計 `subtree_weight[0]`。
- `largest`: 頂点 `v` を除いたときの連結成分の重みの最大値。

空グラフでは、根へアクセスする前に空配列を返します。

## 処理の流れと不変条件

まず根0から親と訪問順を求めます。木では親以外の隣接頂点は未訪問の子です。
`order` を逆順にすると子が親より先に処理されるため、各頂点の初期値を `weights[v]` として
`subtree_weight[parent[v]] += subtree_weight[v]` を行えば、すべての部分木の重みが確定します。
根は自分へ加算しません。

頂点 `v` を取り除いたときにできる成分は、子 `to` の部分木と、親側の部分に分かれます。
それぞれの重みは `subtree_weight[to]` と `total - subtree_weight[v]` です。
根の親側の重みは0なので、根も同じ式で判定できます。
木には子の部分木同士をつなぐ別の辺がないため、この列挙で全成分を過不足なく扱えます。
`largest <= total - largest` なら、定義どおりその頂点は重心です。
これは `2 * largest <= total` と同値ですが、2倍によるオーバーフローを避けられます。
非負重みなら部分木和と `largest` は全体和以下なので、全体和が `T` に収まれば中間演算も収まります。

最後の判定を頂点番号の昇順で行うので、結果のソートは不要です。
辺リスト版は両方向の隣接リストを作り、同じ処理へ委譲します。
重みなし版は全要素1の重み配列を作り、重み付き版へ委譲します。

## 計算量の根拠

訪問順の作成と判定では、それぞれ各頂点・各辺を定数回だけ処理します。
部分木の重みの計算は各非根頂点を1回処理します。木の辺数は $n-1$ なので全体で $O(n)$ です。
3本の配列と辺リスト版の隣接リストに $O(n)$ の空間を使います。
再帰を使用しないため、長い道でも呼び出しスタックの深さは増えません。

## 改造時の注意点

現在のAPIは木であることを前提とし、一般グラフを完全に検証するものではありません。
森へ対応させる場合は成分ごとの走査と全体和が必要です。
負の重みを許すと部分木和が全体和以下という保証がなくなり、重心の存在も保証できません。
浮動小数点数への変更では、集計誤差や半分との比較を別途設計する必要があります。
辺重みの付与だけでは、この頂点重みに基づく重心は変わりません。
重み0を許すと重心が3個以上になる場合があります。例えば道の両端だけに等しい重みがあり、
途中の重みがすべて0なら全頂点が重心です。結果を最大2個と決めつけてはいけません。

重心分解へ拡張するときは、削除済み頂点を除く現在の成分ごとに部分木の重みを求め直します。
元の木全体の `total` や `subtree_weight` を再利用してはいけません。
重みでの分割は頂点数の半減を保証しないため、通常の重心分解の深さの保証が必要なら重みなし版を使います。
単一重心を求めるだけなら結果の先頭を選べますが、空グラフを別扱いしてください。

## 改造後の確認

空グラフ、1頂点、2頂点、奇数長・偶数長の道、星、平衡木を確認します。
小さいランダム木では、各頂点を実際に除いて残る連結成分を列挙する愚直解と比較します。
頂点番号の置換・辺の順序や向きの変更でも結果が正しいこと、長い道でも処理できることを確認します。
これらのケースは `test/tree_centroid_test.cpp` に用意しています。
重み付きについても、全重み0、1頂点への重み集中、半分ずつの分割、重心が3個以上の場合、
符号付き・符号なし整数の上限、ランダム重みを付けた木と愚直解の比較を用意しています。
