# Lazy Segtree の実装解説

[使用法に戻る](../lazy_segtree.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/lazy_segtree.hpp)

## 内部データと不変条件

列長 `n_` と、`n_` 以上の最小の 2 冪 `base_` を保持します。
`data_` に区間集約、内部ノードの `lazy_` に未伝播の更新、`pending_` に
更新の有無を保存します。木の高さも保持し、点アクセス時の祖先伝播に使います。
更新の有無を別に持つため、更新型 `F` に等値比較は要求しません。

各ノードの `data_` はそのノードへの更新を反映済みです。
`lazy_` は子へまだ反映していない更新です。
新たな更新 `f` を重ねるときは `composition(f, lazy_[v])` として、
古い更新の後に新しい更新を作用させます。

## 更新・取得

区間更新は区間が完全に覆うノードへ更新を適用し、それより下への操作を保留します。
部分的に交差する場合は保留中の更新を子へ伝播してから再帰し、親を再集約します。
区間積も完全被覆では `data_` を使い、分割が必要な場合だけ伝播します。
左の結果、右の結果の順に `op` を使うため非可換な演算も扱えます。

`get` と `set` は根から対象の葉まで伝播します。
`set` では葉を置き換えてから祖先を再集約します。
根は常に全体の更新を反映しているため、`all_prod` は伝播せず取得できます。

## 境界探索

通常のセグ木と同様に、片側から部分木を丸ごと採用し、
述語が偽になる部分木だけを下ります。
子へ下りる直前に更新を伝播します。
`max_right` は集約の右へ、`min_left` は集約の左へ部分木の積を追加します。
単調な述語の下では更新・区間積・境界探索はいずれも $O(\log(n+1))$ です。

## O(n) の全要素取得

`to_vec` は内部ノードを根から子の順（配列添字の昇順）に走査し、
すべての遅延更新を葉まで伝播します。その後、実際の葉だけをコピーします。
内部ノードの個数は $O(n)$ なので、全体で $O(n)$ です。
`get` を各要素に呼び出す $O(n\log n)$ の方法は使いません。

伝播は親の集約値を変えず、子の集約値を親と整合させます。
したがって走査後に親を再計算する必要はなく、その後の操作も正しく継続できます。
埋め草を含む区間全体に更新が適用されないよう、更新範囲は常に `[0,n_)` 内に限定します。

## 改造時の注意と確認

アフィン変換のように更新の合成が非可換の場合、`composition` の順序が特に重要です。
また区間長を必要とする更新では `S` に長さを保持し、単位元の長さは 0 にします。
長さのみを指定したコンストラクタは単位元列を作るため、実データの長さを 1 にした
葉の列が必要なら、その配列を明示して構築します。

テストは ACL と配列による参照実装に対し、区間アフィン更新、点更新、置き換え、
取得、境界探索を比較します。文字列連結で集約順を、アフィン変換で合成順を確認します。
全要素取得の前後の更新、繰り返し取得、未伝播タグを持つコピーの独立性、空の木、
2 冪でない列長、関数ポインタとラムダの両形式も検証します。
