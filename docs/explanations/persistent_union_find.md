# Persistent Union Find の実装解説

[使用法に戻る](../persistent_union_find.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/persistent_union_find.hpp)

## 目的と基本原理

併合前の状態を保持し、任意の過去の状態から分岐できます。版 `a` から `(0,1)` を併合した版 `b` を作っても、`a` の連結性は変わりません。全配列をコピーする代わりに、変更経路だけをコピーする永続配列を使います。

## 内部データ

`parent_or_size_` は内部の `persistent_array` です。`root_` が版の根、`nodes_` は版間で共有するノード配列で、各ノードは `value,left,right` を持ちます。番号0は未生成部分で、値は `default_value_=-1`。`group_count_` は版ごとに保持します。

## 処理の流れと不変条件

永続配列の `set` は二分木上で対象葉までの経路を新しく作り、他の子を共有します。`merge` は2つの根を探し、サイズと親の2箇所を更新して新しいオブジェクトを返します。親木にはサイズ併合だけを使い、旧版を書き換える経路圧縮はしません。これによりどの版からも同じ古いノードを安全に参照できます。

## 計算量の根拠

親木の深さは $O(\log N)$、永続配列の1回の取得も $O(\log N)$ なので、根取得・併合は $O(\log^2 N)$。成功する併合ごとの追加ノードは $O(\log N)$、初期化は未生成部分を共有して $O(1)$。`groups` は $O(N\log^2 N)$ です。

## 改造時の注意点

`node_count` はその版だけでなく共有プール全体の確保数です。古い版を捨ててもプールの一部を個別解放しません。経路圧縮をそのまま移植すると永続性を壊します。`nodes_` の追加で vector が再確保されるため、再帰更新をまたいで要素参照を保持しないでください。

## 改造後の確認

同じ旧版から異なる併合をした2版、同成分の再併合、コピー後の更新を確認します。各版を独立した通常の Union Find で再現して比較します。
