# Mo の実装解説

[使用法に戻る](../mo.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/mo.hpp)

## 目的と基本原理

配列の区間クエリを並べ替え、隣り合うクエリ間の変更量を減らすオフライン手法です。`[1,4)` から `[2,5)` なら左の1要素を削除し右の1要素を追加すればよく、区間全体を計算し直しません。

## 内部データ

`queries_` に半開区間、`order` に処理順を持ちます。区間内容や答えはライブラリが保存せず、利用者のコールバックが保持します。内部の `left,right` が現在の区間です。

## 処理の流れと不変条件

左端を幅Bのブロックに分け、同ブロックでは右端を昇順/降順へ交互に並べます。`run` は現在の空区間 `[0,0)` から追加・削除コールバックで目標区間へ移動し、元のクエリIDで `answer` を呼びます。偶奇で右端の向きを変えて端からの戻りを減らします。

## 計算量の根拠

移動数の上界は概ね $O(QB+N^2/B+N)$。`B=max(1,floor(N/sqrt(Q)))` で釣り合わせ、ソート $O(Q\log Q)$ と各移動のコールバック費用を加えます。クエリ保存・並べ替えの空間は $O(Q)$ です。

## 改造時の注意点

左右で意味が違う集約は4種類のコールバックを分けます。2種類版は左右共通に使える場合だけです。`run` のたびに内部は空区間から始まるので利用者側の状態も空へ戻します。途中で配列の値を変更するオンライン用途にはそのまま使えません。

## 改造後の確認

空区間、重複クエリ、Q=0、左右の拡大縮小が連続する例を確認します。各区間を独立に計算した答えと元ID順で比較します。
