# LIS の実装解説

[使用法に戻る](../lis.md) / [実装](https://github.com/sen469/kyopro-library/blob/main/lib/kyopro/lis.hpp)

## 基本原理と内部データ

`tails[k]` に、長さ `k+1` の増加部分列の末尾として、比較順で最も小さい値を持つ
元配列の添字を保存します。末尾が小さいほど、後続の要素を追加しやすくなります。
値のコピーや最大値の番兵ではなく添字を持つため、任意の比較可能な型を扱えます。

## 更新と二分探索

配列を左から処理します。狭義増加では現在値以上の末尾を最初に持つ位置、
広義増加では現在値より大きい末尾を最初に持つ位置を二分探索し、現在の添字で
置き換えます。該当位置が末尾を超えれば、新しい長さの部分列が作れたので追加します。
最終的な `tails.size()` が答えの長さです。

比較関数を変更すると、同じ不変条件をその比較順で使えます。
狭義では `compare(tail, x)`、広義では `!compare(x, tail)` を満たす間、
二分探索の左端を右へ進めます。`std::greater` では減少部分列になります。

## 復元

`tails` の要素をそのまま並べても、元の添字順に対応するとは限りません。
復元時は、現在値を長さ `k+1` の末尾として使う直前に、
その前の長さの末尾 `tails[k-1]` を `previous[i]` に記録します。
最後の末尾から `previous` を逆にたどって反転すると、元の添字が昇順の解になります。
広義増加でも、前の末尾を更新前に記録することで同じ要素を複数回使うことを防ぎます。

## 計算量と改造時の注意

各要素の処理に $O(\log(L+1))$、復元に $O(L)$ なので、全体は
$O(n\log(n+1))$ 時間です。長さだけなら末尾の添字列に $O(L)$、
復元では `previous` に加えて出力を保存するため $O(n)$ 空間を使います。

`lower_bound` 相当か `upper_bound` 相当かを取り違えると、重複値の扱いが変わります。
また末尾を置き換える選び方により返る解は変わるため、辞書順最小や最も早い添字を
選ぶ保証を追加する場合は別の復元方針が必要です。

## 確認方法

二重ループの DP を参照解として、狭義・広義と昇順・降順の組み合わせを比較します。
復元結果の長さ、添字順、元配列との一致、値の単調性も確認します。
空配列、全要素同一、単調増加・減少、整数型の端点、文字列、独自比較型と
重複の多いランダム列をテストします。
